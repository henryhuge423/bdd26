# P28 implementation and verification

The specification defines one change to the placement of trainable encoder blocks. The P28 entry point uses the P27 model and shared training loop with the frozen P28 allocation.

1. In an isolated LM1 worktree, exercise a CPU test of exact trainability, parameter count, frozen tensors, cross-arm loading and training dispatch. Run the new test before installing the driver. Run P28 and adjacent regressions after implementing the driver.
2. Adapt the P27 V100 witness to verify nonzero gradients and updates in blocks 1 and 23. Keep the original control trace comparison in both seeds. Seal the source and run the existing fit-only smoke workflow with C and I. Require both complete checkpoint reloads, BF16 execution, fixed-image output and measured resource bounds.
3. After checking the smoke's actual exit and readiness record, recheck current storage, accounting and scheduler admission. Bind one formal submission to the sealed source and record the job ID and queue state. Publish the research documents and verified code with the normal GitHub fast-forward workflow.
