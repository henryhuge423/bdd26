## 1. 背景与动机

- **EF-P2 判定（2026-10-05）**：ΔDead PQ +.00699、ΔmPQ +.00068、ΔbPQ −.000009、strict mPQ −.00030——Dead 可提升，聚合指标不动，strict 残留小税。
- **稀释算术（诚实前提）**：mPQ = 19 组织 × 5 类平均，Dead 仅在少数组织-类组合有 GT；实测传导率约 10%（Dead +0.7pt → mPQ +0.07pt，≈ 种子噪声 ±.21pt 的一半）。**本线不主张靠 Dead 拉动 mPQ**；主张"稀有类恢复 + 无聚合损失 + 单模型成本"。
- **干扰证据（H1 的来源）**：LKCell 分割更好、分型更差；x2 Dead 增益带 bPQ 税；CP1 类型边界被扰乱；M2 以 bPQ 换不显著 Dead。
- **瓶颈在检测级**：Dead GT 漏检 38.5%（其它类 8–15%），内部漏检 ~.35；匹配 Dead 分型正确率 ~.55–.61。⇒ 解耦必须作用于 NP/HV（类无关的检测通道），只做 TP 分型级解耦不对准瓶颈。
- **Dead GT 稀缺与集中（最大风险来源）**：每折含 Dead 图约 65–97 / ~2600–2900（≈2.5–3.5%）；top10 图占 Dead GT 43–51%；fold3 34 张 Uterus 图主导。专家分支可能学成"少数图的专家"。

## 2. 文献定位（初步核实）

- [GS-MoE（arXiv 2609.18688）](https://arxiv.org/abs/2609.18688)：generalist + specialist 分支恢复低 prevalence 类（最高 +0.60 F1），聚合指标不降。领域为多模态分类/检测（RadImageNet），非 H&E、非实例分割、非 PQ 协议。
- [Semi-MoE（arXiv 2509.13834）](https://arxiv.org/abs/2509.13834)：专家为**任务级**（分割/SDF/边界），半监督腺体分割（GlaS/CRAG）。
- 未发现"类解耦专家 + 细胞核实例分割 + PanNuke 官方 3-fold 协议 + 等参对照"的正面工作。检索为 2 轮 arXiv API + 2 篇摘要核实（WebSearch 限流至 2026-10-13）；**实现前须再深查一轮**（MICCAI/TMI/Papers with Code/PubMed），如撞车只降级叙事、不隐匿。

## 3. 假设、主张与端点

- **H1（前提，闸门 B/C 检验）**：Dead 组与常见类组在共享 decoder 上存在**容量级**梯度冲突，而非仅决策阈值冲突。
- **H2（方法）**：单模型内嵌 Dead 专家分支 + 效用门，可在聚合指标不损（护栏）的前提下恢复**内部** Dead 召回。
- **论文主张**：*Generalist–specialist decoupling for rare-class nuclei instance segmentation*——机制证据 + 方法 + 成本对比；**不主张 mPQ SOTA**。
- **主端点（预注册）**：确认轮 ΔDead PQ（3 折 × 3 种子均值，vs 同种子 C0）点估计 ≥ +.005；护栏 ΔbPQ、Δstrict mPQ 不低于预声明容忍量（容忍量沿用匹配种子配对差值 SD 规则在实现计划冻结）。dev 轮（split1 × 2 种子）只做配置选择与初筛：两种子同号为进入条件。
- **次级端点**：内部 Dead 漏检率、专家新增候选匹配率与误报率、推理成本 p50/p95（vs x1、vs x1+x2+EF 两模型系统）。

## 4. 架构

- **模型**：`CellViTUNI`（`src/nucseg/cellvit/model.py`）+ 新增 `dead_branch`。encoder、NP/HV/TP 三分支、tissue head 一律不动。
- **dead_branch**：与 `_branch` 同构（全宽，输出 64ch 特征），末端两个 1×1 head：`np_dead`(2ch) + `hv_dead`(2ch)。专家必须自带 HV——新增候选若没有分水岭几何则无法成实例（x2 的教训）。
- **监督**：从 GT inst+type 现成构造——`dead_mask` = Dead 实例像素；HV 目标用同一 `hv_targets(dead_inst, hv_min_size=基座值)`。
- **损失**：与主分支同式损失族（NP 通道 / HV 通道），具体复用现有损失实现，实现计划核对。
- **推理**：dead 通道走同一分水岭解码路径（Dead 专属 decode 常数小菜单，验证折选择）→ 候选实例 → 效用门 → 并入基础实例集（EF 式 IoU 去重，沿用 EF-P2 冻结机制）。
- **门分两阶段**：
  - **v0（dev 轮）**：冻结 EF 式几何规则（面积下限菜单 {identity, 30, 60}，验证折选择）——不引入学习，隔离"架构"问题；
  - **v1（确认轮/组合阶段）**：路线 B / E3 的 cross-fit 效用学习（`P(match)·E[IoU|match] > q/2` 代理）。训练候选必须训练折内部 cross-fit 产生；验证折只做冻结候选族的校准/选择。

## 5. 训练配方

- 与基线逐字相同：130 epochs、batch 16、encoder 前 25 epoch 冻结、lr 3e-4、ExponentialLR γ.85、sampler γ.85、原增强、无 TTA、final checkpoint。
- **Dead 稀缺处理（决策点③，默认改用损失掩蔽而非采样改动）**：专家分支损失**仅在 Dead 阳性图上计算**（HV+NP 通道）；阴性图上专家 NP 通道可选 BCE 负约束。菜单 = {阳性-only（默认）， 阳性 + 阴性 BCE}，验证折二选一。
  - 不用 sampler 过采样：C1 完全平衡采样为负结果，改采样会动主分支训练分布；
  - 不用 pos_weight：97% batch 纯负会主导 BatchNorm 统计与负梯度。
  - 主分支损失逐像素语义完全不变。
- `hv_min_size` 与基座一致；基座是 hv30 还是 hv8 由闸门 A 决定。

## 6. 闸门（训练前全部通过才进 dev 轮）

| 闸门 | 内容 | 预冻结继续条件 |
|---|---|---|
| **A** | E2a 四臂对照（在跑，val fold2） | ΔDead(x1_hv8 − x1_hv30) ≥ 0.5 × ΔDead(x2_hv30 − x1_hv30) ⇒ DSB 基座换 hv8，C0/C1 同步换；若 x1_hv8 复现 ≥90% 且无税 ⇒ HV 支持解释全部互补，架构线降级为机制证据，回到用户决策 |
| **B** | 梯度冲突探针（≤1 GPU·天） | 在冻结 base 配方上，Dead 像素组 vs 常见类像素组损失分别反传，取共享 decoder 参数梯度算余弦；冲突（余弦<0）批次比例 ≥ 30%（任意但预冻结的阈值）或逐层显著为负 ⇒ 通过 |
| **C** | L0 决策解耦上界（免训练，val fold2） | 按类 NP 阈值 / 解码常数小菜单若已得 ΔDead ≥ +.005 且 bPQ 税 ≤ .001 ⇒ 架构解耦不必要，本线关闭 |
| **D** | Dead oracle 上界（现成 FN 审计材料） | 全部内部漏检 Dead 以 IoU=0.7 oracle 加入后 ΔDead ≥ +.01 ⇒ 通过（57% FN 为贴边残片，天花板必须先够高） |

## 7. 对照与轮次

- **C0 基线**：直接复用 E2a 的新鲜 `x1_hv30_seed{19,1}`（闸门 A 后可能为 hv8 版本），不重跑。
- **C1 等参 dense**：把专家分支参数量等量摊宽回 NP/HV 分支，同种子同配方——分离"解耦"与"参数量"（审稿人必问）。
- **C3 成本参照**：x1+x2+EF-P2 两模型系统（材料现成，E0 成本分析口径）。
- **dev 轮**：split1 × seeds{19,1} × {DSB, C1} ≈ 4 runs（每 run ≈1.1–1.3× 基线时长 ≈ 10–20 A100·h 含推理评测）。val fold2 选择 → 冻结 → 单次读测试折（多样性限制如实记录：测试折已多轮复用）。
- **确认轮**：3 折 × 3 种子 × {DSB, C1}（18 runs，45–90 A100·h）；C0 缺的种子在实现计划中盘点补齐。
- 评测：`nucseg.metrics.pannuke_eval`，last checkpoint，3-split mean 报告；触碰 plumbing 即跑 `python -m pytest -q`。

## 8. 视觉审查协议（用户 2026-10-07 指示）

- 冒烟后与 dev 轮结束各一次：专家 NP/HV 图、新增候选（TP/FP 分列）、C1 对照的分层 montage（组织 × 贴边/内部 × 面积），交 **sonnet 子代理盲审**（不告知来源臂）。
- 审查目标：系统性伪影（BN 统计漂移、全图高频触发、"Uterus 专家"退化）。发现则修后重训，不做事后挑选式补救。

## 9. 预算与存储

- 闸门探针 ≤2 GPU·天 + CPU；dev 轮 10–20 A100·h；确认轮 45–90 A100·h；总量 ≤120 A100·h，落在研究复盘 §7"机制与审计 60–150"档内。
- 存储：每 run 权重+日志 ~2–4 GB × ≤22 runs < 100 GB；写入前 `df` 检查，批量产物优先 LM2（项目存储规矩）。

## 10. 风险与止损

- **最大风险**：Dead 阳性图太少（65–97/折），专家学成少数图专家 → §8 视觉审查 + 候选匹配率按组织分层兜底。
- dev 轮两种子不同号、任一护栏失败、或闸门任一失败 ⇒ 本线关闭，只保留机制探针证据，不升级算力。
- **不做**：TP 级 MoE 主线、全 decoder MMoE、跨模态、新数据划分、测试折阈值菜单扩容。

## 11. 决策记录（2026-10-07，用户"可以开始"）

1. 主端点 ΔDead PQ ≥ +.005（点估计 + 护栏规则）：**采纳**。
2. 闸门 A 的 50% 换基座线 / 90% 全解释降级线：**采纳**。
3. 稀缺处理：原提案为"sampler 过采样小菜单"，定稿改为**损失掩蔽**（阳性-only 默认，{阳性-only, 阳性+阴性BCE} 菜单）——理由：C1 平衡采样负结果 + 不动主分支分布；sampler 过采样与 pos_weight 均不进菜单。
