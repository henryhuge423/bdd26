# 门控多尺度融合 dev 轮：冻结规格（E5）

起草：2026-10-15（美国东部时间）。状态：**用户 2026-10-15 当前会话指示"继续推进实验"**；本轮按该指示启动最小单变量 dev 轮。
本文在设计冻结后才写结果，端点与门先于任何训练结果固定。未读取任何测试折，未改变任何已关闭路线状态。

## 1. 动机与证据

项目第一短板仍是 **Dead 检测召回**（38.5% Dead GT 与任一预测 max-IoU<.1；内部漏检 .31，其他类 .03–.10；
oracle 插入漏检内部 Dead → Dead PQ +.156）。已按预注册门关闭的路线：CONCH 语言重分型、copy-paste/PixCell 合成、
DSB 专家分支、T0–T3 冻结特征重分型、E3 候选质量学习、KongNet 检测优先复评、训练侧加权/采样、可见片段监督 dev 轮。

在现已核实的 2025–26 文献中，**唯一经架构级改动显著移动稀有类**的证据是 SAFViT（arXiv 2607.27835，CMIG 2026）：
把解码器跳跃连接换成**通道 softmax 门控**（逐像素"信任图"），在不做类重加权/重采样的情况下自报 Dead F1 .373→.518。
其自报基线低于本项目复现的 .4995，因此该增益能否在**本项目冻结协议**下迁移必须实测。

同一门控融合也是本项目新模型（PM-Net）设计表中的既定模块（新模型提案 §3.1"多尺度特征金字塔 + 通道 softmax 门控融合"，
依据行即 SAFViT），且 2026-10-15 综合稿第 4 条要求"基本查询、点初始化与门控融合分别比较，并配**参数匹配的普通 adapter 对照**"。
因此本轮以最小单变量形式在现有 CellViT-UNI 解码器上检验门控融合：它既是 PM-Net 组件的前置证据，也可能直接改善当前主短板。

## 2. 干预（冻结）

基线（A0，已训练、同配方、同种子）：`CellViTUNI._decode` 在 4 个尺度上以 `cat([skip_i, up_i], 1)` 直接融合跳跃特征。

| 臂 | 跳跃路径变换 | 新增参数 | 目的 |
|---|---|---|---|
| G（门控） | `s'_i = s_i * (C_i * softmax(W_i(s_i), dim=1))`，`W_i = Conv2d(C_i, C_i, 1, bias=True)` 零初始化 | Σ(C_i²+C_i)=349,120 | 逐像素通道门控 |
| C（容量对照，条件性） | `s'_i = s_i + W_i(s_i)`，`W_i` 同形状、同零初始化 | 完全相同 | 证明增益来自门控而非额外容量 |

- 逐像素、逐通道；零初始化 → softmax 均匀 → 门值恒为 1，**训练起点函数与 A0 逐位一致**（`C_i * softmax(0) = 1`）。
- 两臂新增参数精确相等（G 与 C 的唯一差别是 `*`+softmax 与 `+`），相对总参数约 362.95M 的 **0.096%**。
- 实现为**加法、默认关闭**：`fusion="plain"` 为默认值，不改变任何既有 run 的数值与参数名，历史可复现性不变。
- **声明边界**：G 是 SAFViT 思想的**最小本地实现**，不是与原文结构/超参逐位一致；本轮不声称复现 SAFViT，
  也不把 SAFViT 的自报数字当作本项目预期值。

- 不新增种子、不扩菜单、不改配方、不做 TTA 或测试折推理。

## 4. 端点与冻结门

**主端点（机制）**：fold2 原图**内部 Dead 匹配率** = 与任一预测 max-IoU>.5 的内部 Dead GT 占比；
配套报告缺失率（max-IoU<.1）。沿用可见性机制报告 `analyze_visibility_supervision.py` 的同一实现与同一对象集合
（fold2 内部 Dead n=741），避免端点漂移。
**质量护栏**：official mPQ、bPQ、strict mPQ、strict Dead PQ 均不低于 A0 −.002；merge 率不高于 A0 +.002。

**疗效条件（阶段 1 判定，须全部满足）**：

1. 两种子内部 Dead 匹配率均高于对应 A0 种子；种子均值提升 ≥ **+.02**；组织分层图像聚类配对 bootstrap
   95% CI 下界 **> 0**（1,000 次抽样，固定种子 20261015，同臂共用同一批重抽样索引）。
2. 两种子 official Dead PQ 变化均 ≥ 0，种子均值 ≥ **+.005**。
3. 质量护栏全部满足（四端点各自不越界）。

**归因条件（阶段 2）**：C 运行后，若 G − C 的内部 Dead 匹配率均值 ≤ 0，或 official mPQ/bPQ 差 < −.002，
结论记为"增益来自额外容量而非门控"，不得表述为门控机制证据。

**停止规则**：任一条件失败即停止；不扩种子、不改门、不救火。全部通过只授权**提出**三 split 确认轮（另立项），
不自动读取测试折。

参照锚点（A0 已训练，fold2 val，同端点）：seed19 mPQ .4840002 / bPQ .6536900 / Dead PQ .1610816 / strict Dead .1174554 /
内部 Dead 匹配率 .635628；seed1 mPQ .4784470 / bPQ .6499801 / Dead PQ .1575460 / strict Dead .1239126 / 匹配率 .591093。

## 5. 验证、成本与可追溯性

- 单测（实现前先写）：`fusion="plain"` 与旧实现**逐位等价**（同权重、同输入 → 输出一致，`branch_param_count` 不变）；
  G 零初始化时前向与 plain 一致（恒等门）；G 与 C 参数计数**精确相等**；门值与梯度有限；配置/断点守卫拒绝 fusion 变更；
  CLI 守卫拒绝与 visibility 臂并用；参数量相对总参数 <0.1%。
- 实现后运行指定环境 `~/.conda/envs/nuclei/bin/python -m pytest -q` 全量回归（改动触及训练/模型路径，必须全量）。
- 单次短 smoke（真实 fold1、batch16、冻结与解冻各一步）检查有限损失、有限梯度、峰值显存与步时；smoke 不用于筛选超参。
- **GPU**：LM1 GPU0/1/4/6 之一，**明确排除 GPU2（本周用户要求）**；单卡串行；启动前复核空闲显存 ≥ smoke 峰值 + 4GiB；
  不使用 LM2 上用户正在运行的卡（当前 3–6）。
- **存储**：LM1 `/data7` 仅余 14G（等于既有运行下限），本轮 run 输出写 **LM2 `/data6`**（余 1.1T）；
  LM1 只保留代码、文档与基线摘要。每 run 完成且 final.pth 校验为完整有限权重后释放 last.pth 优化器状态。
- 记录：commit、config/输入 SHA256、完整命令、seed/fold、PID、日志、峰值显存、墙钟、原始端点。
  禁止覆盖旧工件；队列失败即停，不自动恢复或追加菜单。
