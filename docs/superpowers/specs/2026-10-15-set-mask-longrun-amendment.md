# E6 长程运行预算修订

用户在本聊天明确允许更长训练，并进一步说明：“其实时间长短无所谓；成本无上限，只要不是很多天就好”。这撤销本轮原先因4小时／16GPU·h限制导致的资源停止条件，授权继续既定四次正式实验。

仍只执行 B_seed19 → Q_seed19 → B_seed1 → Q_seed1；fold1训练、fold2开发验证、130epochs、原生256、batch16、workers8、既定优化器／日程、逐epoch完整检查点、最终checkpoint评估、全部质量与推理成本门保持冻结。无额外种子、fold3、重试、配方搜索或依赖升级。

运行保护设为单次训练10小时、整批累计40GPU·h；这是防失控上限，不是科学质量门，也不是预计耗时。按先前真实smoke，串行整批外推约20.82小时，另有数据加载与后续评估／成本测试开销。顺序执行减少同盘检查点写入竞争，并保持原32GiB存储预算估计适用。

复用原始smoke的有限损失／梯度与显存／存储实测。原始4小时准入失败记录保留，通过新的独立准入凭证绑定原报告SHA、修订预算和新源码快照。源码变化仅为显式预算字段与实际截止检查，模型、损失和随机流不变；本轮7项新增预算测试RED→GREEN，全部E6 focused61passed。正式启动前重新核对环境、来源、磁盘、实际空闲显存和重复输出目录。

队列在每阶段核对快照，最多4run，失败停止；不自动恢复或重放。训练完成后逐run独立预测／官方评估；全四次完成后执行固定成本测试和冻结分析。推理成本若无法在规定负载条件下成立，不得声称通过成本门。大检查点留LM2，小型结果及来源返回LM1。

本次裁决：保留单次10小时／整批40GPU·h作为用户宽松授权下的失控保护（代价：最坏约两天）；复用数值相同的既有smoke而不重复GPU计算（风险：当下硬件状态变化，由启动资源复核和节点测试约束）；按原次序串行（代价：更长墙钟时间，但减少I/O与原子临时文件竞争）。
