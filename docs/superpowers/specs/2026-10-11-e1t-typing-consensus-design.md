# E1-T 跨检测器分型共识审计 design spec

起草 2026-10-11｜状态：**待用户批准，未启动。** 依据：T0–T3 预注册门失败后遗留的待检验解释
（findings 2026-10-10：Inf/Conn 标签模糊 / IoU 边缘匹配 / 需联合训练），用与 E1-C 相同的
认识论（检测器共识证据，**不作生物学断言**）检验其中"标签模糊"一项。用户 2026-10-11 批准方向。

## 0. 问题

基模型（split1_seed1 x1）分错类的**已匹配**实例上，未参与该预测的跨折/跨架构检测器是否
系统性支持基模型的类而非 GT 类？若是 ⇒ 标签边界模糊的检测器共鸣证据（与 E1-C 同地位：
跨折训练 + 跨架构的检测器只能从已标注核泛化，其一致反 GT 偏置指向标签可疑）；若否 ⇒
分型缺口更可能是真实模型局限，联合训练假设保持后置。

## 1. 数据（全部现成缓存；CPU-only；fold2 = split1 验证折；fold3 零读取）

- 基：`matched_seed_20261004/p0/split1_seed1/val/base/identity/pred.npz`（x1，identity 解码）。
- jury：E1-C 13 席 − 基 run 本身（split1_seed1-x1）= **12 席**（CellViT 10 + HoVer-Net 2；
  来源 run split1_seed1-x2 已在 E1-C 中排除）。路径：matched_seed p0 val identity npz
  （split1/split3 各 seed）+ `e1_consensus_20261010/hovernet_split{1,3}_fold2/pred.npz`。
  已核实两族 npz 均含 `inst.npy` + `type.npy`。
- GT：fold2 官方 GT（与评测同源）。
- 配对：实例级贪心 IoU ≥ 0.5（与官方评测一致）。jury 成员对某 GT 实例的**类型票** = 该成员
  与此 GT 最大 IoU 的实例，且仅当 IoU ≥ 0.3 才计票（E1-C 口径；IoU ≥ 0.5 作敏感性），
  票值 = 该实例 type。

## 2. 统计量（冻结）

- 分组：**G1** = 基分错（matched 且 base type ≠ GT type）；**G0** = 基分对（matched 且相等）。
- **jury 多数类**（与基无关地定义，避免在 G0 退化）：对每实例统计 jury 票分布（票 = §1 口径），
  多数类 = 得票最多的类，且须满足（总票数 ≥ 3）（最高类票严格多于次高类票）（最高类
  收到**两个训练折**的票）；不满足则记"无多数"，比例单列。此定义不引用基或 GT 的类别。
- 汇报：
  1. **G1 内**：P(多数类 = 基类) vs P(多数类 = GT 类) vs P(多数类 = 其它)，总体 + 按
     GT 类 × 基类分解（重点：Inf↔Conn 双向；X→Dead、Dead→X 单列，不与 Inf/Conn 合并）；
  2. **G0 对照**：P(多数类 ≠ GT 类 | G0)——jury 在无争议实例上的本征"翻票率"，用于校准
     G1 数字（G1 的 P(多数类=基类) 超过本底翻票水平才构成系统性信号）；
  3. 图像聚类 bootstrap 95% CI（2000 重复，种子 20261011；同图多实例不独立）；
  4. 敏感性：仅 HoVer-Net 2 席子 jury 的多数票方向（跨架构对照）；票门槛 IoU 0.5；
     总票数门槛 ≥5。
- **预注册解读键**：
  - G1 的 Inf/Conn 对上 **P(多数类=基类) > P(多数类=GT 类)**（聚类 bootstrap CI 分离）且
    G1 的 P(多数类=基类) 高于 G0 本征翻票率 ⇒ "Inf/Conn 标签边界模糊的检测器共鸣证据"；
    分型方向以该解释收档（bPQ−mPQ 缺口中存在不可由当前标签监督消除的成分），最终报告
    如实写"非生物学断言"。
  - **P(多数类=GT 类) 占优或两者无分离** ⇒ 标签模糊解释不被支持，分型缺口记为模型局限；
    联合训练假设保持后置、不因此启动训练。
  - Dead 的模式无论向哪边都单列描述，不并入 Inf/Conn 结论（形态极端、样本少）。

## 3. 护栏

- fold-guard（只允许 fold2 / split1 val 视角）；不读 fold3；纯缓存重放，无新推理、无训练。
- 不据结果修改任何冻结成绩；E1-T 只驱动解释与报告措辞，不开新训练线。
- 分析脚本在计算任何统计量之前冻结（本 spec 获批即冻结；先提交脚本再跑，含种子与列名）。
- jury 与基同族（CellViT 配方）的相关性如实披露：跨种子、跨训练折成员不独立于基的
  泛化模式；HoVer-Net 子 jury 为唯一跨架构对照。
