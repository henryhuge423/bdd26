# 下一步研究计划：先验证能否学到，再决定是否扩展

**2026-10-09 起草，10 月 10 日修订｜研究建议，尚未启动新实验。** 本文结合阶段四结果与当天的分类上限分析，更新 10 月 6 日方案的执行顺序。已完成实验的结果不变；新的训练、标注和算力投入仍需单独确认。

## 1. 现在做到哪一步了

基线复现、统一评测、误差分析和针对性改进实验已经完成。当前最需要补的是：找到一个有证据支持、又能用较低成本验证的学习问题。

| 工作 | 当前结果 | 对下一步的影响 |
|---|---|---|

| CONCH 重分类、加权采样、已测合成方案 | 没有获得可确认的整体收益 | 不重复相同配方；新分类实验必须说明它增加了什么证据 |

本次重新执行 `verify_report3.py`，108 项差值全部通过；`verify_report4.py` 的输出与冻结快照完全一致。成本修正由同一份计时记录重算，没有新 GPU 测量。历史 P0–P3 的完整来源检查仍存在旧种子清单与后续同名目录冲突，不能写成全量复现已通过。

### 一处需要先纠正的解释

分类脚本中，`inf_conn` 的选择条件是**真值类别属于 Inflammatory 或 Connective**，没有要求预测类别也属于这两类。因此，mPQ .4995 → .6141（+.11461）表示“修正这两类真值对象的全部已匹配错分”带来的变化，约为全类别修正增益的 70%。它不等于“Inf↔Conn 双向混淆独自造成了 70% 的分类损失”。纠正一次错分，还会改变原预测类别的误报数，不能把这个比例解释成可相加的类别贡献。

同样，分类 oracle 的 .6632 接近 bPQ 的 .6653，只是数值接近。两种指标的匹配与聚合不同，不能把 bPQ−mPQ 直接拆成纯分类损失。这里最可靠的信息是：**在已有几何结果上，使用真值改类别可以明显改变 mPQ；现实分类器能做到多少，尚无答案。**

## 2. 推荐取舍：一个主实验，一项并行审计

**建议先做固定实例几何的轻量分类实验，同时推进 E1 候选盲审。暂缓新的分割架构、全图 x2 训练和生成扩量。**

两个问题不能混在一起：

- **分类问题：**已经找到的核，现有特征或实例上下文能否帮助判断类别？它直接关系到整体 mPQ，初筛不需要重训分割器。
- **候选问题：**x2 多报出的对象里，哪些是真实核，哪些是碎屑、轮廓偏差或重复分割？它决定 Dead 候选学习是否值得继续。

E1 不能直接回答“网络特征里是否有可用信号”，也不能自动提供可靠的 Inf/Conn 分类标签。因此，不应把所有分类工作都排在 E1 完成之后；但也不能凭分类 oracle 很高就跳过验证，直接训练第二套大模型。

### 为什么暂不优先其他路线

1. **完全拆成检测网和分类网：**改变太多因素，且增加成本，难以解释结果。先在固定几何上验证分类增益，才知道是否值得拆分。
2. **裁剪一致性：**仍是合理备选，但 E2a 没有证明裁剪是剩余尺度效应的主因。必须先看到真实边缘对象上的对应误差。
3. **学习率日程：**编码器解冻时学习率已很低，值得记录；但“看起来不合理”不等于已证明它限制性能。暂不与结构、尺度同时改动。
4. **更多生成数据：**现有二值条件生成器没有可靠的类别控制，缺少新的监督来源，单纯扩量没有充分依据。
5. **更多种子或更大 GPU：**可以估计训练波动，不能修复重复观察测试集和缺少独立标签的问题。

## 3. 主实验 T：固定几何，检验实例分类的可学习空间

### 假设与最小设计

**假设 T：在不改动核的数量和轮廓时，实例级特征包含原像素多数票没有充分利用的类别信息。** 若成立，应能先由简单读出器获得验证收益；不需要一开始就设计复杂模块。

开发先限定 split1：fold1 用于学习，fold2 用于验证，fold3 不用于这一轮选型。冻结 x1 的检查点、实例图、解码参数和原分类结果。新增方法只替换最终类别，不增删实例、不重画轮廓。

首轮最多比较四种配置，不同时扫描组织先验、类别阈值、裁剪尺寸和网络深度：

| 配置 | 作用 | 要回答的问题 |
|---|---|---|
| T0 原多数票 | 固定基线 | 原方法是什么水平？ |
| T1 实例内类别概率均值 | 不训练的聚合对照；背景处理事先固定 | 收益是否仅来自投票方式？ |
| T2 冻结 TP 特征的实例池化 + 线性分类器 | 只训练小型读出器，使用现有 `tp_feat` | 已有特征是否足够，只是读出方式不合适？ |
| T3 T2 + 一圈局部上下文 | 与 T2 保持相同输入维数和分类器容量；上下文宽度预先固定 | 核外局部信息是否带来额外价值？ |

T3 可用实例池化向量与固定宽度邻域池化向量的等维组合，不先引入额外编码器。若实际实现需要拼接导致维数加倍，应同步加入等维容量对照，而不是把更大的头所获收益归于上下文。首轮不增加模型预测组织先验；真值组织标签不得在部署路径中当作免费输入。

### 训练标签与预测轮廓要分开处理

- 第一轮可在 **fold1 的真值实例区域**上提取冻结特征，训练五类分类器。全部训练配置仅由 fold1 内部确定；已训练的编码器见过 fold1，内部切分不因此成为新的独立数据。
- 主要验证必须在 **fold2 的预测实例轮廓**上完成，使用原始 GT 计算最终指标，不能只报真值框或真值掩码上的分类准确率。
- 真值区域与预测区域的差异要单列：前者的诊断只说明标签或特征是否可分，后者才接近部署条件。
- 未匹配预测也必须保留在最终评测中；只对成功匹配的核计算准确率，会遗漏分类造成的新增误报。
- 若要改成“用模型生成的候选训练分类器或质量头”，应另建训练折内部的交叉拟合候选。不能把分割器训练过的图上的候选当成未见样本，也不能把验证折同时用作新头训练集和独立选择集。

这一步刻意把“类别能否读出来”和“候选筛选能否学出来”分开，避免首轮就承担昂贵的候选生成与集合学习。

### 与以前 CONCH 失败实验的区别

CONCH 负结果表明，已试的外部图文特征和融合方式没有提供有效增量。T2/T3 检验的是当前分割器内部特征的实例级读出，以及固定局部上下文的作用，信息来源和读出方式均可明确控制。它仍可能失败；不能预先断言原 TP 头已饱和，也不能把“换成一个小头”本身当作创新。

### 怎么判断是否继续

所有性能指标以 0–1 为单位。下面是**供实验规格采用的初筛建议值，不是已冻结规则，也不是预测收益**。应在运行前，结合标注重复性、用途和预算一次性确定，不按本轮结果反向放宽。

- 主指标为官方 mPQ，同时报告 strict mPQ、五类 PQ、每组织结果和新增错分。bPQ 在固定几何下应不变；若有变化，先查流程，不能解释为方法收益。
- 建议把 **ΔmPQ ≥ .003（百分制 0.3 分）**作为进入确认轮的最低点估计，同时要求配对图像区间下界大于零、strict mPQ 不下降，Dead PQ 的点估计下降不超过 .002。逐组织和 rare-class 区间仍须完整披露；通过这一开发筛选不等于证明非劣性。
- 最佳学习配置必须超过 T1，且在两个预先固定的分类头训练种子上方向一致。如果 T1 已解释全部收益，就保留简单聚合结论，不继续加深网络。
- 若 T2 已达到 T3 的水平，不继续增加上下文模块。若只有真值掩码诊断提高、预测轮廓上的结果不提高，暂停新分类结构，先研究轮廓污染和训练—推理输入差异。
- 若收益只来自把无该类真值的图像报成该类，或 strict 指标下降，停止该配置。不能用官方指标的缺类规则掩盖误报。
- 计算完整推理增量：特征导出、池化、分类与 I/O 都计入。可暂以 **相对 x1 不超过 1.2 倍**作为轻量方案的设计目标；这是待测目标，不是已有成本结论。若超出，须与同时间预算的 TTA 或已冻结对照比较，再决定是否继续。

若 T0–T3 都未通过，不立即换大分类器补救。先记录失败位置：标签本身难以区分、内部特征读不出、预测轮廓破坏信号，还是收益被误报抵消。只有得到新的、可检验的解释，才立下一项实验。

## 4. 并行审计 E1：弄清新增候选是什么

**E1 的任务是描述候选和标注的分歧，不是证明 PanNuke 漏标，也不是替模型制造有利真值。**

沿用四类来源：x1 检出对象、x2 独有且被接受的候选、x2 独有但被拒绝的候选、随机背景窗口。首批建议共 200 个窗口，四组原则上各 50；按组织与触边状态分层抽取并记录入样概率。分层不足时按事先规则处理，不临时挑选有利样例。随机背景抽的是窗口，不与候选对象共享未经定义的“匹配率”分母。

### 两阶段盲审

1. **先只看图像。**给两名独立评审同样的目标位置和上下文，不显示模型来源、置信度或 GT 是否匹配。记录真实核、非核结构、当前视野不确定；若判断为核，再标完整/截断/多个碎片等状态。尽可能保留最小轮廓标注。
2. **再核对轮廓与标注。**第一阶段答案封存后，显示候选和原 GT 轮廓，区分边界偏差、合并、过分割、可能漏标等。否则评审无法判断几何失败，但又会被先展示的 GT 诱导。
3. **分歧仲裁单列。**保留两份原始答案、仲裁结果和不确定项；报告一致性及不确定比例，不把不确定强行并为假阳性。

两名评审应具备相应病理形态判断能力。模型或语言模型可辅助组织材料，不能代替独立专家给出生物真实性结论。若暂时没有专家，先完成抽样方案，不把代理标签写成 E1 已完成。

200 个窗口只用于检查审计是否可行，不足以保证 rare-class 亚组的统计功效。结果按入样概率加权，并保留图像、切片或患者聚类；同一窗口的多个核不能当作完全独立样本。若患者信息不可得，应明确只支持图像层面的结论。

### 审计结果如何改变路线

| 观察到的主要情况 | 后续动作 |
|---|---|
| 多数无匹配候选是碎屑或背景 | 不开“正样本未标注”路线；仅在简单特征能区分时考虑质量筛选 |
| 真实核较多，但主要是形状、裁剪或实例单位不一致 | 优先做边界/可见实例诊断，不先提高类别置信度门槛 |
| 存在可重复确认的疑似漏标 | 单列独立专家评测，保留官方 GT 成绩；未经扩展验证不宣称数据集系统漏标 |
| 评审对核是否存在都难以一致 | 先完善标签规范或取得更合适图像，暂停监督学习 |
| 有可靠有效候选，且图像/特征可预测其效用 | 才进入训练内交叉拟合的候选质量学习 |

若 T 实验提示 Inf/Conn 标签模糊，需另建分类审计样本，覆盖混淆与非混淆对象。E1 原有抽样偏向尺度候选，不能直接用于估计整个数据集的分类标签噪声。

## 5. 只有通过前一阶段，才开展后续训练

### 分类方向通过：先做一个小型确认轮

锁定最简单的胜出配置，再扩到官方三划分、匹配的三个基线种子。每个划分只从自己的训练数据学习分类器，分类头也使用事先规定的最后一轮，不靠测试成绩挑检查点。多个头种子和多个分割器种子分别记录，不把大量头重复当作更多独立分割器。

确认轮需回答：收益能否跨种子、跨组织保持，strict 指标是否支持同一结论，成本是否仍满足目标。只有这些条件成立，才值得讨论联合训练、适配层或实例分类蒸馏。若简单线性读出已经足够，贡献应写成结构诊断与低成本改进，而不是包装成全新大架构。

### E1 支持候选学习：从简单质量预测开始

先用面积、边界标记、形状和原预测分数做低维模型，预测与标注匹配的概率及掩码质量；与冻结 EF-P2、只按面积筛选比较。训练候选来自训练折内交叉拟合，验证只用于事先限定的选择，测试不参与。

此阶段至少会涉及新的分割器训练，成本明显高于 T 的固定特征初筛。先测一个代表性运行再申请预算，不能把完整 cross-fit 当成免费的 CPU 后处理。

集合网络不应先于独立候选评分。现有添加机制对重叠作了限制，应先说明为什么仍需学习候选间关系。只有独立评分加固定去重不够，且出现可测的交互误差，才增加集合模块。教师蒸馏同样后置；教师新增目标若混入大量误报，压缩只会传播错误。

### 裁剪或日程方向：每次只替换一个解释

仅当 E1 或 T 的输入差异诊断给出相应证据，再选择其中一条：

- 裁剪路线先区分视野删除信息与 token 网格平移，比较普通裁剪增强；人工裁剪上的改善必须落到自然边缘对象上。
- 日程路线只预先选择一种解冻学习率调整，与原日程保持更新步数、数据增强、尺度和目标门槛一致；不同时更换编码器或解码器。

两条都不应与主实验一起全面铺开。

## 6. 数据边界与统计报告

1. **PanNuke 已是反复使用的研究基准。**不读取新的测试结果做本轮选择仍然必要，但不能因此称最终三划分结果为全新、独立的确认性测试。重分图像或补种子也不能消除过去的观察。
2. **split1、split2 共用 test fold3。**报告官方三划分平均；重采样时两个 split 使用相同的图像/病例索引。另列不重复测试 fold 的诊断，不能把九组配对称为九个患者队列。
3. **区分模型随机性与数据不确定性。**种子结果单列；有患者/切片标识时按对应单位重采样，没有时明确只做图像条件分析。不能把细胞数当独立样本数。
4. **外部验证必须与主张对应。**已使用过的 CoNIC、MoNuSAC、PUMA 只能作为固定外部复验。无五类标签的分割集不能验证分类收益，无 Dead 标签的集合不能验证 Dead 泛化。类别映射、未知类别处理和来源重叠需在评估前固定。
5. **最终保留一次真正未参与开发的验证。**优先新患者/新中心，模型和选择规则先冻结；若暂时没有这样的数据，就把结论限制为复用 PanNuke 上的机制与方法研究。
6. **保留原始协议。**自训用最终检查点，最终主表仍用 `nucseg.metrics.pannuke_eval`；all-data 发布权重不能当测试基线。任何快速分类评估都要与 canonical evaluator 的最终结果核对。

## 7. 近期安排与预算边界

以下按依赖关系排列，不承诺未经测量的 GPU 小时数。

| 阶段 | 交付物 | 资源与进入条件 |
|---|---|---|
| 先固定问题 | T0–T3 的数据划分、特征、指标、阈值、成本边界；E1 抽样与盲审表 | 文档与 CPU；先批准一页实验规格 |
| 低成本初筛 | T 的验证结果、错误迁移表、实际耗时；E1 首批双评结果 | 单卡提取必要特征、轻量分类头；专家工时并行安排，不重训分割器 |
| 判定是否继续 | 对照、置信区间、按预定规则的继续/停止结论 | 无论结果正负，都先结束这一轮，不追加菜单挽救结果 |
| 条件性确认 | 仅一个胜出方向的三划分多种子结果与独立数据方案 | 再按实测成本申请算力；候选 cross-fit 单列预算 |

缓存优先保存每实例向量和必要元数据，不保存全量稠密特征图。作为容量示例，10 万实例的 64 维 float32 向量约为 25.6 MB，尚未计 ID、标签及其他元数据；这只是算术估计，不是当前数据总量。大规模训练和 H100 申请应等通过初筛后再讨论。

**最有价值的下一份结果，应是一张能回答以下问题的表：固定轮廓后，哪一种最简单的分类读出真正改善了验证 mPQ，strict 指标是否同向，增加了多少成本。** 若答案是都没有，也应据此停止；同时用 E1 判断 Dead 路线究竟还缺标签证据、几何处理，还是可学习的候选信号。
