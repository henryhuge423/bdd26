# 模型结构、实验复盘与后续方向

**2026-10-09 修订。** 本文面向有基础机器学习知识、但不熟悉细胞核分割的读者，解释模型怎样工作，以及现有实验支持哪些判断。下一轮的具体建议见[研究计划](RESEARCH_NEXT_2026-10-09.md)。

原稿中的部分机制解释比实验结论更强。本次保留结果，收窄这些解释；尤其更正分类 oracle 中“70% 来自 Inf↔Conn 互混”的说法。数值以冻结实验产物为准，研究日志用于追溯过程。

## 0. 先看要点

1. **任务有两步：找到每个核，再认出它的类别。** 只改类别不能找回从未检出的核；找到更多核，也不保证整体指标提高。
2. **HoVer-Net 和 CellViT-UNI 都有三条输出分支。** NP 判断核前景，HV 描述核内相对位置，TP 判断类别。分支有各自的解码参数，但仍共享上游特征。
3. **Dead 存在明显漏检，但不能说它只有检测问题。** 原始诊断中，38.5% 的 Dead 真值与任一预测的最大 IoU 小于 .1；已匹配 Dead 的类型正确率约为 69%。两个数字描述不同人群。
4. **x2 能改善部分检测，也有代价。** EF-P2 筛选两倍尺度新增候选后，Dead PQ 小幅提高，整体指标仍有不确定性；两模型系统约需 x1 的 6.1 倍推理时间。
5. **分类还有多大可学习空间，尚未验证。** 真值辅助改类别能使 mPQ 从 .4995 变为 .6632，但这不是模型可达到的成绩。
6. **下一步先做小实验。** 固定实例轮廓，比较简单的类别聚合与实例级特征读出；并行推进独立候选盲审。暂不据此训练两个完整网络。

## 1. 任务和指标

输入是一张 256×256 的 H&E 病理图块，输出是每个细胞核的轮廓和五类之一：Neoplastic、Inflammatory、Connective、Dead、Epithelial。Dead 包含凋亡与坏死核，不只指凋亡。

PQ 同时考虑漏检、误报和匹配后的轮廓质量。预测与真值的 IoU 大于 .5 才能匹配；分类评测还要求类别对应。官方 mPQ 按项目实现的图像、组织与类别层次汇总，五类等权；bPQ 不区分类别。

官方类别 PQ 不计入图中没有该类真值时的该类误报，strict 版本会计罚。因此，稀有类官方 PQ 上升时，要同时检查 strict 指标。mPQ+ 是另一种多类匹配与汇总口径，不是纯检测指标。

课程中的基线复现、按组织和类别评估、错误分析及针对性实验均已有结果。是否继续追求更高整体 mPQ，是后续研究取舍，不应把尚未证明的收益写成已完成贡献。

## 2. 两个模型怎样工作

### 2.1 共用特征，分别解码

HoVer-Net 使用 ResNet 编码器，再由三条独立解码分支生成 NP、HV 和 TP。CellViT-UNI 沿用三分支任务设计，但以 UNI 的 ViT-L/16 编码器和多尺度跳接构建解码输入；它不是只替换编码器而保持其余结构完全不变。

CellViT-UNI 的主要组成如下：

- UNI 的第 6、12、18、24 层 token，经适配层形成不同尺度的特征。
- 原图另经过 `skip0` 的浅层卷积，保留全分辨率局部信息。
- NP、HV、TP 三条独立解码分支读取同一组特征，再分别输出 2、2、6 个通道。
- 另有组织分类头读取全图的 cls token；它不等于已经验证有效的类别先验。

三条分支不是一个解码器末端的三个线性头，而是各有完整解码参数。另一方面，它们共享编码器和跳接特征，因此不能称为彼此独立的模型。源码见 `src/nucseg/cellvit/model.py:60–134`；HoVer-Net 分支定义见 `third_party/hover_net/models/hovernet/net_desc.py:43–95`。

### 2.2 训练时分别提供答案

训练标签由真值轮廓构造：

| 分支 | 要学习的内容 | 当前损失 |
|---|---|---|
| NP | 每个像素是否属于核 | focal-Tversky + Dice |
| HV | 核内像素相对本核中心的归一化水平、垂直位置 | 2.5×MSE + 8.0×MSGE；MSGE 在核内计算 |
| TP | 背景及五类核的像素类别 | 0.5×CE + 0.2×Dice + 0.5×逐类 focal-Tversky |

HV 可理解为帮助区分相邻核的两张位置图，不宜把它严格等同于每个像素指向核中心的物理箭头。

面积小于 `hv_min_size=30` 个工作像素的核，HV 目标会被清零。它们仍有 NP 和 TP 监督；HV 的零目标也仍参与相应损失，并非整核被忽略。

训练中的 HV、TP 损失不使用 NP 的硬预测作门控。但三个任务的梯度都会影响共享参数，不能因此说训练完全互不影响。源码位置见 `src/nucseg/cellvit/engine.py`、`src/nucseg/hovernet/data.py` 和 `src/nucseg/hovernet/targets.py`。

### 2.3 推理时，先分出实例，再确定类别

原尺度的默认解码流程是：

1. NP 概率达到 .5 的区域形成前景，去掉小于 10 像素的连通块。
2. 根据 HV 的空间变化计算边界强度，只保留 NP 前景内的有效区域。
3. 从前景中构造种子，用分水岭把相邻核分开；实例只能在给定前景掩码内生长。
4. 在每个实例内统计 TP 的像素类别票数。若背景票数最高，按实现规则取下一类别。

所以，NP 漏掉一个核时，后面的实例分类没有对象可以处理；NP/HV 给出错误轮廓时，TP 也会在这个错误像素集合上投票。这解释了为什么需要分别检查检测和分类，而不能只看一个总分。

它不意味着低 NP 概率必然没有可用信息，也不意味着所有可训练输出融合都无效。现有免训练恢复菜单未成功，支持的是这些已测配方的负结果。

### 2.4 冻结、微调和工作尺度

基线训练 130 轮，前 25 轮冻结 ViT 编码器。初始学习率为 3e-4，每轮乘 .85；解冻时已经约为 5.2e-6。因此，当前配方主要先训练解码侧，再以较小学习率联合微调。

这是值得检验的训练设置，但仅凭学习率曲线不能证明它限制性能。若要更改，需保持数据、更新次数和其他配置一致，单独做日程对照。

ViT-L/16 的 token 网格步长是 16 个工作像素，模型又保留了全分辨率浅层通道。小核可能受采样与特征尺度影响，但不能仅按一个核覆盖几个 token，断言其语义信息已经丢失。x2 是对同一图像插值放大，没有增加新的光学观测；它改变了网络接收信息的方式。

E2a 发现：按原图面积配平 HV 门槛后，内部 Dead 的匹配率仍从约 61.3% 提高到 71.0%。这支持存在门槛以外的尺度相关因素，尚不能把剩余效应全部归因于 token 数量。9.59% 是两项点估计增益的比值，不是因果分解。

## 4. 梯度探针不能替我们回答所有结构问题

DSB 探针比较的是 **Dead 与常见类像素组的代理损失梯度**，不是直接比较 NP 检测任务与 TP 分类任务的梯度。测量也只覆盖训练完成的检查点，不覆盖整个训练过程。

因此，下列推断都不成立：

- 余弦为正，所以检测和分类从不互相干扰；
- 原 DSB 被停止，所以所有特征融合或第二级分类器都无效；
- 同向梯度意味着两套模型的预测错误完全相同。

当前合理的决策是：原 DSB 方案没有满足自己事先设定的前提，不继续投入原训练预算。若改换为容量分配、类别读出或上下文建模假设，应单独提出廉价检验，不能沿用原方案的批准或结果。

E1 独立候选盲审只能帮助判断对象是否真实、轮廓与标注如何分歧。它既不是特征可分性实验，也不自动构成第二级分类器的训练标签。

## 5. 分类 oracle：有多大理想空间，尚不能说明能学到多少

### 5.1 怎样计算

`scripts/typing_oracle.py` 读取已冻结、已经评测过的三个 split 基线测试预测。在实例轮廓完全不变的条件下，对 IoU>.5 的已匹配对象替换类别，再用 `RetypeEvaluator` 重算官方 mPQ：

- `current`：原始类别；
- `oracle`：所有已匹配对象都改为对应真值类别；
- `inf_conn`：仅对真值属于 Inflammatory 或 Connective 的已匹配对象改类别，原预测可以是任意类别。

未匹配预测的类别不变，漏检和轮廓错误也仍然存在。因此这是一个具体的真值辅助干预，不是所有可能重分类方式的严格全局最大值。

该分析没有调参，但访问了历史测试产物，且未预注册。它可以提出假设，不能作为新的独立测试证据。原脚本与缓存保留，本次只核对选择逻辑和缓存数字，没有重新扩大测试分析。

### 5.2 冻结结果

| 干预 | 三划分平均 mPQ | 相对原结果 |
|---|---:|---:|
| 原始分类 | .49951 | — |
| 所有已匹配对象按真值改类别 | .66322 | +.16371 |
| 真值为 Inf/Conn 的已匹配对象按真值改类别 | .61412 | +.11461 |

第三行的增益约占第二行增益的 70%。**不能将它改写为“Inf↔Conn 互相错分占了 70%”。** 脚本只按真值类别筛选，包含这两类被错分成其他类别的情况；纠错也会减少其他预测类别的误报。mPQ 是非线性指标，这个比例不是可相加的混淆贡献。

split1 的逐类结果（原始 → 全类别 oracle）为：Neo .570→.666、Inf .440→.720、Conn .418→.595、Dead .142→.411、Epi .575→.659。它说明分类值得研究，也提醒我们不要把 Dead 简化成纯检测问题。

bPQ=.6653 与 oracle mPQ=.6632 接近，不能据此宣称两者差距全部是分类损失。二者匹配与汇总口径不同；分类 oracle 仍留下检测错误，而官方缺类规则也会影响分数。

### 5.3 还缺三个答案

1. **标签是否足够可靠？** 部分 Inf/Conn 形态可能难以区分，但本项目尚未完成独立分类标签审计，不能先把上限差距归为标注噪声。
2. **特征是否包含可利用信息？** CONCH 的已测重分类失败，不能证明当前 TP 特征、浅层特征和实例上下文均无价值。
3. **收益能否在预测轮廓上成立？** 真值掩码上的高分类准确率不等于部署收益；轮廓偏差、未匹配预测和缺类误报都需保留在评测中。

原稿列出的预期 mPQ 增益和二阶段推理倍数，没有对应实测支撑，本次删去。也不再使用“已发表天花板约 .51”或“无人超过某个类别分数”概括整个文献范围。

## 6. 为什么先试实例读出，不先拆成两个网络

当前模型已经共享特征、分别解码。把检测和分类拆成两个完整网络，会同时改变容量、特征、优化和推理成本，很难用一个结果说明是哪一部分有效。

更便宜的第一步是固定检测结果，依次比较原多数票、实例内概率均值、冻结 TP 特征的实例池化与线性分类器，再加入一个受控的局部上下文对照。这些实验直接回答：已检出的对象上，是否还有简单、可利用的分类信息？

如果简单方法都没有收益，应先查标签、特征和预测轮廓的差异；如果已经有收益，再检验跨种子稳定性和成本。只有固定特征不够、额外图像信息又有证据时，才考虑重新编码实例 crop。逐核运行编码器可能很贵，不能预先写成只增加 1.2–1.5 倍成本。

EF-P2 的约 6.1 倍成本描述的是特定双尺度推理与融合流程，不能外推为任意双网络系统的固定成本，也不能直接证明检测—分类解耦不值得做。

## 7. 当前建议

**主实验：固定几何的轻量分类可行性；并行工作：E1 独立候选盲审。** 前者面向整体 mPQ，后者决定 Dead 候选路线是否值得继续。

这一顺序与原先“所有训练都等 E1”的表述不同。原因是两项工作回答不同问题：分类初筛可先使用现有训练标签；候选效用学习则需要训练内交叉拟合与可靠的候选质量证据。

若分类初筛通过，再做一个配置的三划分多种子确认；若 E1 支持有效候选可以可靠筛选，再做简单质量预测。裁剪一致性、日程调整、集合学习和蒸馏均按对应证据后置，不同时开展。具体对照、停止条件和数据边界见[下一步研究计划](RESEARCH_NEXT_2026-10-09.md)。所有这些仍是建议，没有因此启动新训练。
