## 0. 摘要（一页版）

1. **任务**：给 256×256 H&E 图块，输出每个细胞核的实例掩码 + 5 类之一（Neoplastic /
   Inflammatory / Connective / Dead / Epithelial）。评分 mPQ = 五类 PQ 等权平均（每类要先
   "找到"IoU>0.5，再"认对"类）。
2. **结构**：HoVer-Net 与 CellViT-UNI 共享同一设计——编码器映射到共享特征，三个**参数完全独立**
   的解码分支各出一张逐像素图：NP（是不是核）、HV（每像素指向自核中心的箭头）、TP（6 类概率，
   含背景）。推理时后处理以 NP 为门：HV 的 Sobel 边界能量只在 NP 前景内有效，分水岭只在 NP
   掩码内生长，TP 只在最终实例内做多数票。
3. **核心诊断**：Dead（占实例 1.6%）的损失在**检测**不在分型——38.5% 的 Dead 真值核完全漏检
   （NP 概率均值 0.16），而匹配到的 Dead 有 69% 判对类。
4. **失败复盘的共同形状**：重分类够不着从未被检出的核；调损失权重加不出新信息；搬运真实外观
   会污染类型边界；无类别条件的生成器造不出 Dead 外观；检测优先架构恰在同类贴核上更差；放大
   分辨率是"整体精度换 Dead"的明码标价交易；专家分支赖以成立的前提（梯度冲突）被实测证伪
   （余弦 +0.749、0/64 为负）。
5. **新诊断（本轮新增）**：mPQ 与 bPQ 之间 **.166 的差距几乎全部丢在分型上**——把所有匹配
   实例改成正确类别，mPQ 从 .4995 → **.6632**（≈bPQ）；其中 **Inflammatory↔Connective 互混
   单独占 +.115（约 70%）**。整体 mPQ 最大的未开发空间不在 Dead，而在常见类分型。
6. **结论**：现有证据不支持把架构完全解耦成两个独立网络（无梯度冲突可解除、两阶段先例更差、
   系统级双网络 EF-P2 仅 +.0007 mPQ / 6.1× 成本）；有数据支撑的替代方案是"共享底座 + 第二级
   实例 crop 分类器"，属新训练轮，排在 E1 独立标注之后。

## 1. 任务、评分与课程要求

**评分（PQ）**：对每个真值核找一个预测核，重叠 IoU>0.5 才算"找到"；"找到"之后类别还必须判对。
官方 mPQ 对"图中不存在的类"的误报不罚（置 NaN，因此偏乐观，稀有类尤甚）；strict mPQ 计罚；
mPQ+ 采用多类配对。

**课程要求（`docs/our_project5_nuclei_segmentation.pdf`）三项**：① 复现一个强模型（✔ HoVer-Net
.4564 / CellViT-UNI .4995，官方 3 折协议）；② 按组织×类别用 PQ/AJI 评测（✔）；③ 分析
merged/split/missed 并**测一项针对性改进**（✔ 已测十几种）。要求的是 targeted improvement，
**不是整体 SOTA**——"显著提高整体准确率"是战略选择，而非义务缺口。

## 2. 两个模型的结构

### 2.1 总体数据流

原版 HoVer-Net（`third_party/hover_net/models/hovernet/net_desc.py:81-93`）：ResNet50 编码器 +
共享解码主干，末端特征同时喂三条并列解码分支（np/hv/tp）。CellViT-UNI
（`src/nucseg/cellvit/model.py:60-134`）只把编码器换成 UNI（ViT-L/16，病理基础模型），解码侧
仍是三条独立分支。**分叉点之后，三条路再无信息交换。**

```
输入 256×256×3
 ├─ skip0: 原图上两层3×3卷积（全分辨率，浅层边缘/纹理）──────┐
 └─ UNI ViT-L/16：24层注意力 → 16×16=256个token（1/16分辨率）  │
      第6/12/18/24层token → 反卷积上采样成多尺度跳跃特征 ───────┤
                     （同一组5层共享特征，含skip0）             │
        ┌────────────────┼─────────────────┐
   NP分支解码器        HV分支解码器        TP分支解码器     另有 tissue_head
   →1×1卷积 2通道      →1×1卷积 2通道      →1×1卷积 6通道   （读cls token，19组织）
   "是不是核"概率       每像素指向自核中心   每像素6类概率
```

两个关键细节：
- **不是"一个解码器+三个头"，是三个各自完整的解码器**（`np_branch`/`hv_branch`/`tp_branch`，
  `model.py:83-84`），参数互不共享；
- **"潜空间"不止深度语义**：ViT 语义全部经过 1/16 分辨率的 token 网格，另有一条全分辨率浅层
  卷积通道 `skip0`（`model.py:76`）补回被 patch 化丢掉的细节。

### 2.2 训练视图：三个分支各自稠密监督，互不参考

每张训练图预先算好三张答案图（`src/nucseg/hovernet/data.py:96-97`）：`np_map`（逐像素二值）、
`hv_map`（逐像素到自己核中心的 x/y 距离，由 GT 掩码几何算出）、`tp_map`（逐像素 0–5 含背景）。
损失（`src/nucseg/cellvit/engine.py:131-146`）：

| 分支 | 损失 | 备注 |
|---|---|---|
| NP | focal-Tversky + Dice | 全图稠密 |
| HV | 2.5×MSE（全图，教"核外为零"）+ 8.0×MSGE（**只在核内像素**） | HV 答案构造时 <30 工作像素的核被清零（`hovernet/targets.py:47-48`，`hv_min_size`） |
| TP | 0.5×CE + 0.2×Dice + 0.5×逐类 focal-Tversky | **含背景类**——TP 的背景通道本身是隐式检测器 |

所以训练时 TP/HV **不**以 NP 的预测为条件。这是刻意设计：NP 的 argmax 不可微，无法直接当门；
训练早期 NP 还很差，用差掩码筛选监督会让误差层层传播；稠密的独立监督让每个分支处处都有满强度
梯度；TP 的独立背景通道还留下了一份可供后处理反哺的冗余信号。

### 2.3 推理视图：NP 硬性门控 HV 与 TP

解码链（`src/nucseg/postproc/recovery.py:120-155`，u=1 与官方逐位一致）：

1. NP 概率 ≥0.5 → 连通域 → 丢 <10px 碎块 → 前景掩码 `blb`；
2. HV 归一化 → Sobel(ksize=21) 算箭头突变能量；**`overall − (1−blb)` 再截零——边界能量在 NP
   前景之外清零**；
3. 前景减边界带 → 5×5 椭圆开运算 → 每核一个种子；**分水岭 `mask=blb`——实例只能在 NP 掩码内生长**；
4. TP 逐像素 argmax 在实例内**多数票**；票数第一是背景则取第二
   （`third_party/hover_net/models/hovernet/post_proc.py:160-175`）。

即：**生产端解耦（训练），消费端门控（推理）**。这一设计也有实测到的代价：NP 把核切歪时，TP
就在错误的像素集合上投票（逐像素多数票与概率 argmax 有 1.2–1.6% 的分歧，其中匹配且类型正确的
仅 16–20%）；小核的 HV 答案被清零 → 贴着大核的小核箭头平坦 → Sobel 能量微弱 → merge。

### 2.4 训练配方：编码器冻结与微调

（`src/nucseg/cellvit/engine.py:230-247`，`runs/cellvit_uni/split1/config.json`）

- 130 epoch；**前 25 epoch ViT 编码器冻结**（`freeze_encoder(ep < 25)`），只训解码侧；
- 学习率 3e-4 起、0.85/epoch 指数衰减——**解冻时刻（ep25）学习率已衰减到 ~5.2e-6**（初始值的
  1.7%），到 ~ep60 低于 1e-7。实际的训练过程是：冻结底座、全力训练解码器 25 轮，然后全网在
  极小学习率下轻柔地联合微调；
- bf16 autocast 前向；512 输入且解冻后需逐块梯度检查点；组织×类别加权采样。

设计理由：UNI（ViT-L，约 3 亿参数）是十万张病理切片预训练出的底座，而每个 split 只有约 2,600
张训练图，用满学习率微调会冲坏预训练特征。**推论**：两个"独立网络"若共享同一个冻结 UNI 初始化，
特征便高度同源，解耦换来的独立性比想象中少——CONCH 二次意见零增量的教训正源于此。

### 2.5 结构性含义：为什么小核对这套结构天然难

ViT 的语义全部经过 1/16 分辨率的 token 网格——一个 20px 的小 Dead 核只覆盖约 1.5 个 token，
大部分信息只活在 `skip0` 的浅层卷积特征里。这是三件事的共同根源：x2（每核 token 数 ×4）真实提升
Dead 检出（内部匹配率 61.3%→71.0%）；HV 门槛只解释 x2 Dead 增益的 9.59%、尺度本身解释其余；
换更大编码器在 mPQ 上只挪 1–2 点、对 Dead 无济于事。

## 3. 失败复盘：各线路为什么不行

### 3.1 核心诊断（一切的前提）

- 38.5% 的 Dead 真值核完全漏检（与任何预测 IoU<0.1；其他类 8–15%）；
- 匹配到的 Dead 69% 判对类；漏检 Dead 的 NP 概率均值 **0.16**——NP 头根本没"看见"。

**每条线路的成败几乎都能归结为"有没有碰到 NP/HV 这条检测链"。**

### 3.2 总表

| 线路 | 想法 | 结果 | 结构性原因 |
|---|---|---|---|
| A1 CONCH 重分类 | 病理图文模型二次判型 | mPQ .4951→≤.4953，零变化 | 只动 TP 头；没检出的核没有实例可重分类；CONCH 自然分布 Dead 精度 ~.10 |
| A2 加权/采样/找回 | Dead 加权×11、平衡采样、小核加权、96 种后处理 | 全部无效（小核加权 3 种子 ΔmPQ −.0010、ΔbPQ −.0024） | 加权改变"多在乎谁"不改变"能看到什么"；NP 0.16 的信息不在输出图里，后处理变不出信息 |
| B1 copy-paste | 真实 Dead 核贴图 | test ΔDead **−.031**，匹配 Dead 判对率 .69→.61 | 贴图染色/光照/融合失配，注入 subtly 假的 Dead 样本，搅浑类型边界 |
| B2 PixCell 合成 | 掩码条件扩散整图合成 | mPQ .4900（基线种子区间底部） | **结构性死结**：ControlNet 条件是二值掩码、无类别通道，729 个保留对象中 Dead=0（教师 P(Dead)≤.005） |

## 4. "三头统合 / 融合网络"的证据边界

三个分支是**同一组共享特征的三次读出**，错误高度相关——这不是猜测，是被定量测过的：

- DSB 闸门 B：共享解码器上 Dead 与常见类损失梯度余弦 +0.749（0/64 为负）；
- CONCH 外部二次意见：零增量；
- TP 背景/Dead 通道反哺 NP 前景（`recovery.py` 的 β/k_dead）：96 配置全空；
- 逐类解码阈值（闸门 C，仅测 Dead）：+.0021 < +.005 线；
- M/S 杠杆（同类合并+贴边碎片丢弃）：bPQ +.002~.003，Dead 不动；
- 跨**模型**输出级融合（P2/EF-P2）：唯一存活，但匹配率 39–43%、成本 6.1×。

**信息上的死结**：只读三张输出图的融合网络（无论多深）只能对已有输出重新加权，不能创造 NP 从未
激发过的检测（NP 概率 0.16）。输出级融合的天花板已被上述六个方向的实测框住。

**特征级统合**（读 skip/特征图而非仅输出）= 可训练第二级 = 新训练轮。文献形态：Mask R-CNN 式
两阶段、CPP-Net 耦合式；本项目对应实现 `dead_branch`（`model.py:88-91`）被 DSB 闸门关闭。
立项前提——"漏检 Dead 在浅层特征里可见吗"——正是 **E1 独立标注**要裁决的第一件事。

## 5. 整体 mPQ 的账：分型 oracle 诊断（本轮新增）

### 5.1 方法

用 `RetypeEvaluator`（`src/nucseg/metrics/fast_retype.py`，只在实例类别变化时精确重算官方 mPQ，
聚合方式与 `pannuke_eval` 相同）对三个 split 的已保存测试预测（无 TTA、last checkpoint）做
只读诊断：把所有 IoU>0.5 匹配实例的类别直接改成 GT 类，实例几何完全不动。当前值与官方评测
复核吻合（.4951/.4930/.5104）。复现：

```bash
python scripts/typing_oracle.py --out-json runs/analysis/typing_oracle_20261009/summary.json
```

**边界**：这是对已冻结测试产物的审计型访问（量化天花板），不是调参入口；任何由此发展的杠杆
（如组织先验、逐类阈值）**只能在验证折上调参**。

### 5.2 结果

类别构成（fold3，66,654 个 GT 核）：Neo 42.7% / Conn 26.2% / Inf 16.2% / Epi 13.3% /
**Dead 1.6%**。匹配实例整体判对率 .864；混淆集中在 Inf→Conn 11.8%、Conn→Inf 10.9%。

| | 当前 mPQ | 分型 oracle | 差距 |
|---|---:|---:|---:|
| 3-split 均值 | **.4995** | **.6632** | **+.164** |
| 只修 Inf/Conn 错分 | | .6141 | **+.115** |

逐类（split1，当前 → oracle）：Neo .570→.666、**Inf .440→.720**、**Conn .418→.595**、
Dead .142→.411、Epi .575→.659。

对照 bPQ=.6653：**bPQ 与 mPQ 之间 .166 的差距几乎全部丢在分型上**（完美分型的 mPQ≈.663≈bPQ，
数值自洽）。**整体 mPQ 最大的可回收分数不在 Dead，而在 Inf↔Conn 互混——它单独占分型损失的
约 70%**；分 split 稳定（+.169/+.167/+.155）。

### 5.3 可达性折扣（如实声明）

- oracle ≠ 可达：Inf/Conn 混淆有相当部分是真实的形态模糊加标注噪声（文献里所有方法在官方协议下
  Inf/Conn 都停在 .42–.48，无人超过 .50；PQ+ 口径下 Inf .579 说明的是同一件事）；
- "用外部先验修分型"已测过：CONCH 融合对整体 mPQ 零增量——TP 头对单像素证据的提取已基本饱和；
- Dead 的指标权重并不低（mPQ 五类等权，其 oracle 提升量与 Inf/Conn 同量级）；放弃它的理由是
  六个捕获机制全部实测失败，而不是权重低。

### 5.4 策略排序

| 档 | 内容 | 预期 | 状态 |
|---|---|---|---|
| A（CPU，零训练） | 组织条件化类别先验（模型自带 19 组织头，从未测过——与 CONCH 的"组织条件化提示"是两码事）；非 Dead 类逐类解码阈值（闸门 C 只测过 Dead）；实例级概率均值投票 | 合计 +.002~+.008 | 未测，`fast_retype` 支持验证折精确调参 |
| B（已训权重组合） | TTA 已测 +.005；**种子集成从未测过**（split2/3 各 3 种子在库）；CellViT+LKCell 互补 | 合计也许 +.01，代价 2–4× | 未测；发布权重只能作"系统"行披露 |
| C（一次新训练轮） | LKCell 大核解码器（.508）/ PromptNucSeg 提示选择（.512）/ CellVTA 式 adapter（.506） | **+1~1.5 mPQ，已发表天花板 ~.51** | 按纪律排在 E1 之后；若批准应打 **Inf/Conn 分型 + Connective 检测**（missed_bg .153，常见类最差），不是 Dead |

不值得再试：换更大 backbone（±1–2 点且已在区间内）、更多后处理规则（系统性测空）、x2（对 mPQ 为负）。

## 6. "完全解耦成检测网 + 分类网"的评估

三档解耦的判断：

| 档位 | 形态 | 代价 | 判断 |
|---|---|---|---|
| 现状 | 共享编码器 + 三个参数独立的解码分支 | 1× | 已经是半解耦 |
| 半解耦 | 共享（冻结）UNI + 两套解码器（检测网 NP+HV / 分型网 TP） | 训练便宜，推理 ~2× | 收益证据缺失 |
| 全解耦 | 两个完整网络各自编码器 | 训练/推理 ~2× | 证据指向不值得 |

反对全解耦的四条实测证据：
1. **解耦的理论收益是解除任务干扰，而干扰被测不存在**（闸门 B 余弦 +0.749；审计保留边界：代理
   损失、已训检查点，不能外推到整个训练历程）；
2. **领域先例一致**：PanNuke 原论文的两阶段 Mask R-CNN 明显落后 HoVer-Net；本地版 KongNet
   .346 vs .4995；
3. **系统级双网络已跑过**：EF-P2 = x1+x2 两网络验证门控融合，mPQ +.0007、6.1× 成本——这还是
   尺度真互补的情形，同分辨率两网相关性更高、收益更小；
4. **解耦治不了核心难点**：merge/split 在检测链内部，分型网络读到的已是合并实例；Dead 38.5%
   漏检同理。

支持解耦的一条证据链：分型确实吃放大后的外观细节（du2 对匹配 Dead 的分型 .579 vs .554）。所以
值得考虑的不是两个完整网络，而是**共享底座 + 第二级实例 crop 分类器**（检测仍走 NP/HV/分水岭；
对每个检出实例抠出原分辨率 crop，用冻结 UNI 的 patch 编码加一个小分类头重打类型）：保留共享
特征的好处、把专业化用在账面空间最大的地方（Inf/Conn，oracle +.115）、推理只增加约 1.2–1.5×。
它是新训练轮，其监督信号（实例级可靠标签）正是 E1 要产出的东西；且它的廉价代理实验全部测零
（CONCH crop 级重分类、解码级逐类阈值），"能捞回多少 oracle"目前没有任何正面证据。
