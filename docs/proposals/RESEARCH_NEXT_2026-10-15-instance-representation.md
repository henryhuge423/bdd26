# 下一轮最小对照草案：基本集合查询与高分辨率掩码

2026-10-15，America/New_York。状态：研究建议，可审阅；尚未批准实现或训练。先前可见性/E5 停止规则保持有效。

## 要回答的问题

保留现有 UNI 编码器、原生 256 输入和基本训练配方，使用基本实例集合表示及其必要的监督/解码后，能否比匹配的 CellViT-UNI 基线更好地找回内部 Dead，同时守住整体质量？

这里改变的是“表示+必要损失+必要解码”的实验包。即使获益，也不能分别宣称“取消 HV”“取消 watershed”或“查询本身”是原因。点初始化和参数容量归因需要后续独立对照。

## 三个可选方向与建议

| 方向 | 好处 | 当前主要风险 | 顺序 |
|---|---|---|---|
|基本集合查询 + 高分辨率掩码|避开固定点网格的邻域排斥；不依赖 GT 点推理|512 查询的匹配/训练成本与小对象优化；新包可能没有召回优势|推荐首先冻结这一最小方向|
|点热图 + 动态掩码|可直接诊断点召回与掩码质量|网格/局部峰值/重复处理与掩码输出同时引入变量|作为后续独立初始化对照|
|SAM 式提示掩码|已有核分割先例|骨干、预训练、提示器和分割器一起变化；更难与现有基线归因|作为独立替代路线，暂不并入首轮|

几何审计不能证明第一项会赢。选择它是为了控制变量和降低模块数量。

## 建议首轮范围

- 仅 split1：fold1 训练、fold2 开发验证；不读 fold3，不作测试或三 split 确认。
- 种子 19/1。两臂：B 为匹配 CellViT-UNI 基线，Q 为最小查询实例包。若采用新的可恢复增强流，B 必须同样重训；不能沿用旧 A0 并声称逐样本增强配对。
- 最多四次正式 run，各 130 epochs、unfreeze25、native256、batch16、同 UNI 初始化、采样和增强政策、现有学习率/衰减配方、无 TTA、last checkpoint。
- 所有类别保留原五类 CE 目标；不加逆频重采样、额外类别权重、层次头、jury 软标签、合成数据或新骨干。
- Q 暂以 512 个查询作为容量候选。正式规格必须规定增强后容量溢出 fail-stop，不许静默丢弃 GT。512 的原图覆盖不等于显存或延迟达标。
- 掩码必须通过原生分辨率细化或明确的连续 logits 上采样路径输出；不得以粗二值网格最近邻放大代替，也不得把 HV30 直接变成最终实例面积过滤。
- 不引入点热图 NMS。先用一对一匹配及 no-object 监督处理预测集合；重叠像素和空掩码需有确定性处理。

## 建议冻结的统计判断

下列为待审阅的首轮新规格建议，不改写任何已执行实验的门。

1. 主端点沿用 fold2 原图内部 Dead 集合：max-IoU>.5，对预测类别不作要求。两种子均改善、种子均值至少 +.02，固定 1,000 次组织分层图像聚类配对 bootstrap 的 95% CI 下界 >0。
2. official Dead PQ 两种子均不降，均值至少 +.005。实际 miss=max-IoU<.1 单独计算，不使用“1−matched”代替。
3. 每种子 official mPQ、bPQ、strict Dead PQ 均 ≥B−.002；strict mPQ 每种子不降；merge 率 ≤B+.002。全部五类、组织支持和组织差值共同展示，探索子组不新增通过规则。
4. 同机同负载、batch1、预热与重复测量后的端到端推理 ≤2× B；包含预处理、编码、全部查询掩码和重叠处理，不能只计 backbone 或 MACs。
5. 任一预定门失败则结束该配方；不通过扩种子、改变阈值或追加模块挽救。通过只允许提出进一步归因/确认，不自动读取测试折。

## 实现与资源的前置条件

正式实现规格必须先补齐以下内容，再审阅：

- 查询/掩码模块的精确结构和参数量；点参数是否完全省略，禁止实现时暗中追加。
- 匈牙利匹配的分类与掩码代价、权重、采样坐标、空图损失、各损失归一化；小对象不能因采样不到而失去监督。
- 原生掩码细化的精确路径、分块和梯度保留方式。单纯把 query 计算分块不保证训练激活显存随之下降。
- 冲突、重复、no-object、掩码阈值和像素归属规则；所有选择在看新验证成绩前固定。
- 独立于模型 RNG 的采样/增强状态及恢复证明；不中断基线与查询臂的可比性。
- 空图、非连续 ID、单像素、单轴、非凸/分离实例、边界碎片、密集图与溢出行为的测试。
- CPU 后单卡 smoke：冻结/解冻各一步、有限损失/梯度、实际峰值显存、训练步时、完整推理耗时。smoke 不用于筛选超参数。

资源建议上限：四次正式 run，单 run 最多 4 GPU·h，总预算最多 16 GPU·h，另单独列 smoke≤20分钟；若实际速度不能满足，正式开始前修订预算，不能开跑后自动扩额。该数值是拟议停止预算，不是已测训练耗时。

存储预算建议≤32 GiB，新轮启动前至少 52 GiB 可用以保留 20 GiB 余量；smoke 后按实测 checkpoint/优化器体积重新核算，不能靠删除旧工件达标。当前 LM1 只有约4.7 GiB，不满足条件。不能从历史记录推断 LM2 可用，也不能为查资源新建未经授权的 SSH。

主机、卡号、显存余量与活动作业须在实际派发前核实；保留 GPU2 排除约束，禁止触碰他人/用户作业。现有 broker 复用规则继续适用。
